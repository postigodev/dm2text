# Special Message Parsing Design

## Goal

Improve transcript fidelity for three Instagram Direct structures observed in
group conversations:

- shared posts with a source account and optional caption;
- Meta AI messages with a visible answer plus a presentation badge;
- messages whose nested cards or previews contain profile links that must not
  be mistaken for the message sender.

This change preserves the existing copy-session, collection, anchoring,
ordering, privacy, and performance behavior. It does not add support for new
Instagram surfaces or persist additional data.

## User-visible behavior

### Shared posts

A shared post is represented explicitly instead of flattening its source,
caption, and media marker into ordinary message text.

The transcript format is:

```text
Sender: [shared post by Source account]
  Caption: Full caption text
```

Rules:

- omit `by Source account` when the source cannot be determined;
- omit the caption line when the post has no visible caption;
- preserve visible caption text, including its existing multiline
  normalization;
- do not append a redundant `[image]` marker merely because the post card has
  a preview image;
- if only a source or only a caption is recoverable, emit the partial structured
  result rather than discarding the message.

### Meta AI messages

For a Meta AI message, the copied content is the substantive visible answer.
Presentation-only labels such as `Generated by AI` are excluded from content
selection. If no substantive answer is mounted, the parser returns no message
content instead of presenting the badge as the answer or inventing a fallback.

### Sender attribution

Sender evidence is valid only when it belongs to the message-level sender
chrome. Profile links, avatars, and account names nested inside reply previews,
shared-post cards, or other embedded content cannot identify the outer message
sender.

Outgoing layout inference may inspect only the message-level content wrapper.
It must not infer `You` from alignment internal to an embedded card. When sender
evidence remains ambiguous, existing recoverable `Unknown` handling and group
backfilling continue to apply.

The selected anchor has no special sender behavior. It is parsed by the same
rules as every other message.

## Normalized model

Extend `MessageContent` with an Instagram-independent semantic variant:

```ts
{
  type: 'shared-post';
  source?: string;
  caption?: string;
}
```

At least one of `source` or `caption` must be present before this variant is
created. Instagram DOM discovery remains under `src/instagram/`; transcript
selection and formatting consume only the normalized variant.

Message signatures include the complete normalized content and visible reply
preview, as they do today. Sender and timestamp remain excluded so a message's
identity stays stable when attribution or time evidence changes across
virtualized windows.

## Instagram adapter strategy

`parseMessage` classifies specialized content before running the generic
text/media fallback:

1. Detect a shared-post card from its message-local structural container.
2. Extract its source and caption from descendants of that card only.
3. Detect a Meta AI response and select its substantive answer container while
   filtering known presentation-only labels.
4. Otherwise use the existing text, mixed-content, and media parsing path.

New DOM assumptions are centralized in `src/instagram/selectors.ts` or small
helpers in `src/instagram/parse-message.ts`; they are not distributed through
the transcript or collection layers. Structural fallbacks remain narrow and
message-local so unrelated links or text cannot become sender/content evidence.

Sender parsing separately gathers only direct message-level evidence before
falling back to geometry and existing group resolution. Specialized content
parsing must not alter collection order, anchor selection, or deduplication.

## Formatting

The transcript formatter renders a shared post as one logical message. Its
header stays on the normal sender line, and an available caption is emitted on
the immediately following indented line. Embedded newlines in the caption use
the existing escaped `\\n` convention so transcript records remain
unambiguous.

Reply context continues to prefix the sender line exactly as it does for other
content types.

## Testing

Add anonymized deterministic fixtures and unit tests covering:

- an incoming shared post with source and multiline caption;
- partial shared posts with only a source or only a caption;
- a shared post preview image without a redundant media marker;
- a Meta AI answer where `Generated by AI` is present but excluded;
- a Meta AI structure with no mounted substantive answer;
- an outgoing message whose embedded card contains another account's profile
  link or avatar;
- an incoming media/shared card whose internal alignment must not infer `You`;
- stable signatures for structured shared-post content;
- transcript formatting with replies and multiline captions.

Use synthetic usernames, text, and DOM fixtures. Do not commit real thread IDs,
conversation text, or account metadata.

## Privacy and lifecycle

All extracted data remains transient within the active copy session. The change
adds no logging of message content, persistence, fetch/XHR/WebSocket/beacon, or
extension-originated network transmission. The only permitted external output
remains the user-requested operating-system clipboard write. Existing session
cancellation and cleanup ownership are unchanged.

## Acceptance criteria

- Shared posts use the approved structured transcript format.
- Meta AI output contains the visible answer, never only its presentation
  badge.
- Nested profile/card elements cannot override the outer sender.
- The same sender rules apply to the anchor and non-anchor messages.
- Existing collection, ordering, reply, formatting, cancellation, and cleanup
  tests continue to pass.
- Typecheck, unit tests, and the WXT production build pass within the existing
  lightweight budgets.
