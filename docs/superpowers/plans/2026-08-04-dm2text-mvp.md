# DM2Text MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan inline, task by task. Do not dispatch subagents unless the user explicitly changes that preference. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a lightweight Manifest V3 browser extension that adds “Copy context” to an Instagram Direct message menu, collects the requested number of messages ending at that immutable anchor, and copies a chronological structured transcript.

**Architecture:** A single WXT content script is injected across Instagram so SPA navigation into Direct cannot bypass it, but its delegated handler remains inert unless the current path starts with `/direct/`. Instagram-specific code reads and scrolls mounted DOM windows; pure transcript and collection modules merge those windows and select the immutable anchor. The entrypoint orchestrator owns the full lifecycle through formatting, clipboard, viewport restoration, UI cleanup, and reference clearing.

**Tech Stack:** WXT, Manifest V3, Vanilla TypeScript, native DOM APIs, plain CSS, Vitest, pnpm.

## Global Constraints

- No runtime dependencies.
- No frontend framework.
- No permanent background worker.
- No polling or `setInterval`.
- The only authorized output of collected conversation data is the user-requested write to the operating-system clipboard; DM2Text never persists that data or transmits it over a network.
- DM2Text initiates no `fetch`, XHR, WebSocket, beacon, or extension-originated network request.
- Parse messages only while a copy session is active.
- Create the copy dialog and toast lazily; remove them when closed.
- Never persist or log conversation content.
- Total JavaScript must remain under 60 KB minified.
- Packaged extension must remain under 200 KB.
- Missing sender, timestamp, media, or reply data is recoverable and remains absent rather than being invented.
- Unknown or changed Instagram DOM must fail with a user-visible explanation, never with a destructive action.
- Browser end-to-end automation is outside the initial MVP; verification on real DMs is manual.
- Never copy fewer messages than requested without an explicit confirmation showing the available and requested counts.
- Commit commands are review checkpoints; run them only after the user accepts the preceding deliverable.

## Current-state and DOM research notes

- The checkout contains project instructions and this plan, but no `package.json`, source tree, or Git repository.
- WXT’s current documented pattern is a file-based content-script entrypoint with `matches`, direct CSS import, `postinstall: wxt prepare`, and `WxtVitest()` in `vitest.config.ts`.
- Both inspected URLs use a message scroller with `display: flex`, `flex-direction: column-reverse`, and `overflow-y: scroll`. At the latest message `scrollTop` is `0`; visually scrolling upward produces a negative `scrollTop`.
- One upward scroll caused the mounted window to expand from 21 to 41 groups while Instagram adjusted the scroll offset. Progress must therefore be based on newly merged message identities, not only `scrollTop` or `scrollHeight`.
- The inspected message pane exposed no stable `data-testid`, message IDs, `<time>`, or `datetime` attributes. CSS classes are generated. All DOM assumptions must remain in `src/instagram/` and be covered by anonymized fixtures.
- Message actions appear on hover in this order: react, reply, more. Clicking “more” asynchronously mounts a `dialog` containing native menu buttons. The extension should capture the message before the dialog opens, then use a short-lived observer to inject its action.
- Group and individual conversations share the same high-level scroller/menu behavior, but sender discovery differs: group incoming runs contain profile links, individual incoming runs can inherit the peer from the conversation header, and outgoing messages should normalize to `You`.
- Timestamps are display text rather than machine-readable values. Preserve visible separators/menu timestamps when attributable; otherwise omit `timestamp`.

it('prepends newly mounted older messages and keeps chronological order', () => {
  expect(signatures(mergeWindow(stateOf('c', 'd'), windowOf('a', 'b', 'c', 'd')).messages))

Run: `pnpm test -- src/transcript/merge.test.ts`

Expected: FAIL because `mergeWindow` does not exist.

- [ ] **Step 2: Implement sequence-overlap reconciliation**

Use the longest contiguous overlap between the two chronological signature sequences. Retain the keys of overlapped existing messages and assign a monotonically increasing session-local key such as `m0`, `m1`, … only to unmatched arrivals. On the first window, map `anchorIndex` directly to the assigned session key and retain that `anchorKey` unchanged through every later merge. Never deduplicate through `Set(signature)`, because two identical adjacent messages are valid.

Build `AnchorSnapshot` from the exact first-window index: `occurrenceInWindow` is the zero-based occurrence of the selected signature among equal signatures in that parsed window. Capture its immediate neighbor signatures. The snapshot supports best-effort viewport restoration; transcript selection uses the immutable session key, not a later DOM heuristic. If virtualization later shifts an identical-message run, restoration uses occurrence plus neighbor context and may fall back to the saved scroll offset, but transcript selection never changes its session key.

When multiple overlaps are equally valid, prefer the longest; when still ambiguous, prefer the overlap that preserves the existing anchor occurrence. Keep the anchor as a key stored by the session, independent of future DOM arrival.

export function createCopyContextRequestHandler(
  deps: OrchestratorDependencies,
): (request: CopyContextRequest) => Promise<void> {
  let activeSession = false;

  return async (request) => {
    if (activeSession) {
      deps.closeInstagramMenu(request.menuTrigger);
      deps.showToast('A copy session is already running.', 'warning');
      return;
    }

    activeSession = true;
    try {
      await runCopySession(request, deps);
    } finally {
      activeSession = false;
    }
  };
}

Implement SPA exit detection in `src/instagram/navigation.ts`. This observer exists only while a copy session is active and never parses messages:

```ts
export function watchDirectRouteExit(
  signal: AbortSignal,
  onExit: () => void,
): () => void {
  let exited = false;
  const checkPath = () => {
    if (!exited && !location.pathname.startsWith('/direct/')) {
      exited = true;
      onExit();
    }
  };
  const observer = new MutationObserver(checkPath);
  observer.observe(document.documentElement, { childList: true, subtree: true });
  window.addEventListener('popstate', checkPath);

  const teardown = () => {
    observer.disconnect();
    window.removeEventListener('popstate', checkPath);
  };
  signal.addEventListener('abort', teardown, { once: true });
  checkPath();
  return teardown;
}
```

The orchestrator, not `collectMessages`, owns the complete lifetime:

```ts
async function restoreWithTimeout(
  activePort: CollectionPort,
  snapshot: AnchorSnapshot,
  deps: OrchestratorDependencies,
): Promise<void> {
  const restoreController = new AbortController();
  let restoreTimeout: ReturnType<typeof window.setTimeout> | undefined;

  const timeoutResult = new Promise<boolean>((resolve) => {
    restoreTimeout = deps.setTimeout(() => {
      restoreController.abort(new DOMException('Restore timed out', 'AbortError'));
      resolve(false);
    }, 3_000);
  });

  try {
    const restored = await Promise.race([
      activePort.restoreAnchor(snapshot, restoreController.signal),
      timeoutResult,
    ]);
    if (!restored) {
      deps.showToast('The selected message could not be restored.', 'warning');
    }
  } catch {
    deps.showToast('The selected message could not be restored.', 'warning');
  } finally {
    restoreController.abort();
    if (restoreTimeout !== undefined) deps.clearTimeout(restoreTimeout);
  }
}

type CopyFailureCode =
  | 'layout-changed'
  | 'exact-anchor-missing'
  | 'no-messages'
  | 'invalid-partial-result'
  | 'cancelled'
  | 'left-direct';

class CopySessionFailure extends Error {
  constructor(readonly code: CopyFailureCode) {
    super(code);
  }
}

function failureMessage(error: unknown): string | null {
  if (error instanceof CopySessionFailure) {
    if (error.code === 'left-direct') return null;
    if (error.code === 'cancelled') return 'Copy cancelled.';
    if (error.code === 'no-messages') return 'No messages could be collected.';
    if (error.code === 'layout-changed' || error.code === 'exact-anchor-missing') {
      return 'Instagram changed this conversation layout; no messages were copied.';
    }
  }
  if (error instanceof ClipboardError) {
    return 'Clipboard access failed; no conversation data was saved.';
  }
  return 'Copy failed; no conversation data was saved.';
}

export async function runCopySession(
  { anchorRoot, menuTrigger }: CopyContextRequest,
  deps: OrchestratorDependencies,
): Promise<void> {
  let messages: TranscriptMessage[] = [];
  let transcript = '';
  let port: CollectionPort | null = null;
  let anchorSnapshot: AnchorSnapshot | null = null;
  let dialog: CopySessionDialog | null = null;
  let stopRouteWatch: () => void = () => undefined;
  let abortReason: 'user' | 'left-direct' | null = null;
  const sessionController = new AbortController();

  try {
    stopRouteWatch = deps.watchDirectRouteExit(
      sessionController.signal,
      () => {
        abortReason = 'left-direct';
        sessionController.abort(new DOMException('Left Direct', 'AbortError'));
        dialog?.close();
      },
    );

    sessionController.signal.throwIfAborted();
    const scroller = deps.findMessageScroller(deps.document);
    if (!scroller) throw new CopySessionFailure('layout-changed');

    sessionController.signal.throwIfAborted();
    const initialWindow = deps.parseMountedWindow(scroller, anchorRoot);
    if (initialWindow.anchorIndex === undefined) {
      throw new CopySessionFailure('exact-anchor-missing');
    }
    anchorSnapshot = deps.buildAnchorSnapshot(initialWindow);
    deps.closeInstagramMenu(menuTrigger);

    sessionController.signal.throwIfAborted();
    dialog = deps.createDialog();
    const cancelFromDialog = () => {
      abortReason = 'user';
      sessionController.abort(new DOMException('User cancelled', 'AbortError'));
    };
    dialog.signal.addEventListener('abort', cancelFromDialog, { once: true });

    const requestedCount = await dialog.requestCount();
    if (requestedCount === null) throw new CopySessionFailure('cancelled');
    sessionController.signal.throwIfAborted();

    port = deps.createCollectionPort({
      scroller,
      anchorRoot,
      startingScrollTop: scroller.scrollTop,
    });
    const result = await deps.collectMessages({
      port,
      initialWindow,
      requestedCount,
      signal: sessionController.signal,
      onProgress: (collected) => dialog?.updateProgress(collected, requestedCount),
    });
    messages = result.messages;

    if (result.status === 'cancelled') {
      throw new CopySessionFailure(
        abortReason === 'left-direct' ? 'left-direct' : 'cancelled',
      );
    }
    if (messages.length === 0) throw new CopySessionFailure('no-messages');
    if (messages.length < requestedCount) {
      const partialReason =
        result.status === 'beginning' || result.status === 'stalled'
          ? result.status
          : null;
      if (!partialReason) throw new CopySessionFailure('invalid-partial-result');
      const approved = await dialog.confirmPartial(
        messages.length,
        requestedCount,
        partialReason,
      );
      if (!approved) throw new CopySessionFailure('cancelled');
    }

    sessionController.signal.throwIfAborted();
    transcript = deps.formatTranscript(messages);
    sessionController.signal.throwIfAborted();
    await deps.copyText(transcript);
    deps.showToast(`Copied ${messages.length} messages.`, 'success');
  } catch (error) {
    const message = failureMessage(
      abortReason === 'left-direct'
        ? new CopySessionFailure('left-direct')
        : abortReason === 'user'
          ? new CopySessionFailure('cancelled')
          : error,
    );
    if (message) deps.showToast(message, 'error');
  } finally {
    sessionController.abort();
    stopRouteWatch();
    deps.closeInstagramMenu(menuTrigger);
    dialog?.close();
    if (port && anchorSnapshot) {
      await restoreWithTimeout(port, anchorSnapshot, deps);
    }
    messages.length = 0;
    transcript = '';
  }
}
```

## Known MVP limitations

- Instagram does not expose stable message IDs in the inspected DOM. Sequence-overlap merging greatly reduces duplicate ambiguity, but a long run of visually identical messages with identical metadata may still be indistinguishable after complete virtualization.
- Per-message timestamps are not always present in the mounted DOM. The extension preserves only timestamps it can attribute safely.
- Unsupported attachment shapes are emitted as `[unknown]` rather than guessed.
- Viewport restoration is best-effort because Instagram controls virtualization and may discard the anchor node.
- Initial localization of DM2Text-owned UI is English-only; Instagram menu-trigger recognition is structural and should not depend on the page language.
